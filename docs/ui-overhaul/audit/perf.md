# ultraGrade — performance + correctness audit (HEAD a41dad3, branch ui/flat-overhaul)

Method: measured `client/dist` (gzip -9 via python). Rebuilt once **into the scratchpad** with `--sourcemap` (same hashes as dist; repo untouched, `git status` clean) and attributed bytes per module from the sourcemaps. Library sizes measured by bundling each library on its own with rolldown. `npm test`: client 96/96 pass, server 3/3 pass. Date and id claims were checked with `TZ=America/Toronto node` (scratchpad/tz.mjs).

**Initial load measured: 266.8 KiB gzip (944.3 KiB raw)** across 8 files (index.js, rolldown-runtime, vendor-motion, vendor-react, vendor-supabase, createLucideIcon, vendor-ui, index.css). That matches the ~266.8K baseline. index.html (1.5K), registerSW.js (0.1K) and the manifest (0.3K) add about 2K more, plus Google Fonts CSS and woff2 files from a third-party origin.

## Findings

### P0 broken

- [P0 broken] · auth/demo · client/src/context/AuthContext.jsx:15 · On a first load at `/demo*` the provider returns early. It never calls `getSession()` and never subscribes to `onAuthStateChange`. A client-side navigation out of the demo then lands on a real route with `user === null`, so RequireAuth sends the user to `/login`. Signing in there succeeds at Supabase, but no listener updates `user`. `navigate('/')` (Login.jsx:386/418/427) bounces straight back to `/login`. The user is stuck until a full reload, and a returning user with a valid session is shown the login screen. These demo links reach the real app: TaskItem course badge `to='/grades?course='` (TaskItem.jsx:128) and its "Log grade" toast `navigate('/grades?grade=')` (:31), CourseCard "Next: …" `to="/planner"` (CourseCard.jsx:182), Grades empty state `to="/?new=semester"` (Grades.jsx:166), LifeHub "What expires next? → Profile" `to="/profile"` (LifeHub.jsx:24). · Evidence: early `return undefined` before the subscription, and `window.location` is checked only once in a `[]` effect. · Fix: always subscribe, and only skip the Supabase calls while `useLocation().pathname` starts with `/demo` (or re-run when the path leaves /demo). Also prefix demo-reachable links with `/demo` when `isDemo` is set.

### P1 painful

- [P1 painful] · quick-add/Ask · client/src/pages/Ask.jsx:15-16 · After "Add to ultraGrade", `commit()` sets `committed=true` but never calls `quickAdd.reset()`. The preview and its enabled commit button stay on screen next to "Saved to your plan". A second tap creates every task, grade and class again. `resolved` is still committable because `activeTasks` includes completed tasks. · Evidence: `const commit = () => { quickAdd.commit(); setCommitted(true); }`, and the preview branch is still gated only on `status==='preview'`. CommandPalette avoids this by calling `close()`. · Fix: `quickAdd.reset()` after commit (keep the success line), or disable the button once committed.
- [P1 painful] · quick-add · client/src/components/quickadd/useQuickAdd.js:83-98,129-137 · Take "quiz 1 8/10 and quiz 2 9/10 for CS350" where no "Quizzes" category exists yet. Both items resolve `gradeCategory=null` from the pre-commit `courses` snapshot. The commit loop calls `addCategory` once per item, which creates **two "Quizzes" categories**, each with weight `newCategoryWeight`. The course weight is double-counted (e.g. 2×20%). · Evidence: `resolved` is memoised before the commit, and `commit` never re-resolves or remembers categories it created. · Fix: keep a `Map(courseId+name → category)` inside `commit` and reuse a category created earlier in the same batch.
- [P1 painful] · quick-add/sync race · client/src/context/AppContext.jsx:259-276 + :310 · When quick-add auto-creates a category, `insertCategory` and `insertGrade` are sent in the same tick as independent requests. `addCategory` doesn't `trackPending`, and `addGrade` doesn't chain `afterParent(catId)`. If the grade request commits first, the `grades.category_id` FK and the `grades_owner_guard` trigger (003_production_integrity.sql) reject it. The grade is then rolled back from the UI with a "Failed to save grade" toast. Timing-dependent, but nothing in the code orders the two requests. · Fix: `trackPending(cat.id, insertCategory(...))` in addCategory and `afterParent(catId).then(...)` in addGrade, the same pattern addCourse/addTask already use.
- [P1 painful] · offline sync · client/src/context/AppContext.jsx:74 · `retryQueue.current.set(msg, retry)` is keyed by the **message text**. Add 3 tasks offline and all three call `onSyncError('Failed to save task', …)`, so only the last retry survives. On `online`, 1 of 3 tasks reaches Supabase. The queue also lives only in memory. If the PWA is closed or reloaded before reconnecting, the next `loadAll` replaces local state (AppContext.jsx:57-64), and every task that was "saved locally" is silently lost. This contradicts the offline toast ("changes are saved locally and sync when you reconnect", SyncErrorBridge.jsx:28). Retry results are also ignored (`flush` doesn't check `{error}`). · Fix: key by entity id plus operation, persist the queue to localStorage, and merge unsynced local rows on load instead of replacing them.
- [P1 painful] · offline sync · client/src/context/AppContext.jsx:161-162,219-221,266-272,310-319,359-363 · Add a grade, category, course or class while offline and it **always** rolls back immediately with no retry. There is no `isNetworkFailure` check, unlike addTask/updateTask. An offline user who enters a grade sees it disappear with a "Failed to save grade" toast. updateCategory, updateGrade, update/deleteTimetableEntry, deleteTask, deleteGrade and deleteCategory have neither rollback nor retry, so local and server drift apart until the next load reverts the edits. · Fix: one policy for all mutations: keep the change locally on network failure, queue it by id, and roll back only on a real (4xx) rejection.
- [P1 painful] · quick-add dates · server/routes/quickAdd.js:33 · `currentDate: new Date().toISOString().slice(0,10)` is the UTC date. From 19:00 EST (20:00 EDT) onward in Toronto, the model is told it is already tomorrow. "Due tomorrow" lands a day late. On a Thursday evening, "Friday" can resolve as "today" or as next week's Friday. · Evidence: `TZ=America/Toronto`, 2026-11-17 20:30 → server sends `2026-11-18`, while the local date is `2026-11-17`. · Fix: the client sends `today()` (dateHelpers.toDateStr) plus its IANA `timeZone` in the body. The server validates it as `YYYY-MM-DD` within ±1 day of UTC and uses it.
- [P1 painful] · demo ids · client/src/demo/DemoProvider.jsx:5 · `id = prefix-${Date.now().toString(36)}` has no randomness. Ids created in the same millisecond collide. The demo "Import my syllabus" prompt calls `addTask` twice in one loop (DemoProvider.jsx:61, DemoAssistant.jsx:15), so **both new tasks get the same id**. The result is duplicate React keys, toggling one toggles both, and deleting one deletes both. · Evidence: 5 calls in a loop gave `demo-task-mwkpbrc5` ×5, 1 unique (scratchpad/tz.mjs). · Fix: `crypto.randomUUID()` (already used in AppContext.generateId).
- [P1 painful] · theme/FOUC · client/index.html:18 · The pre-paint script reads `localStorage['ultragrade_settings']`, but settings are stored at `ultragrade_${userId|guest}_settings` (AppContext.jsx:39). The script never finds the key. Light-theme users get a dark (classic) first paint and spinner on **every launch**, then a flip to light when App.jsx:81-94 runs after auth resolves. The `<meta theme-color>` stays `#0b1511`. · Evidence: grep shows no unscoped `ultragrade_settings` write anywhere in src. · Fix: also write `localStorage.ultragrade_theme` from the theme effect and read that in the inline script, or scan keys matching `/^ultragrade_.*_settings$/`.
- [P1 painful] · network exposure (machine policy) · server/index.js:93, client/vite.config.js:76 · The API listens on `0.0.0.0:3001` and Vite dev uses `host: true` (0.0.0.0:5173). On this workstation the wifi firewall zone leaves 1025-65535 open, so the dev API (public `/api/immigration`, token-guarded ICS feed) and the Vite source server are reachable by anyone on the wifi. Render needs 0.0.0.0 only in production. · Fix: `app.listen(PORT, process.env.HOST || (isProd ? '0.0.0.0' : '127.0.0.1'))` and drop `host: true` (or make it opt-in via env). Reach the dev servers from the MacBook with `ssh -L`.
- [P1 painful, suspected] · settings race · client/src/context/AppContext.jsx:121-132 with OnboardingWizard.jsx:63-77 · Onboarding `finish()` fires up to 3 `upsertProfile` calls in one tick (activeSemesterId, permitExpiryDate, studentType). Each carries a full snapshot, and nothing orders them. If an earlier snapshot (studentType null) commits last, the server profile loses `student_type`. On the next launch RequireStudentType sends the user back to /onboarding. Separately, a non-network failure of call #1 that resolves after #3 restores `previous` (from before #1) locally and wipes the later changes. · Fix: coalesce profile writes (debounce, or serialise through a promise chain) and send only changed columns. Roll back only the fields this call changed.

### P2 polish

- [P2 polish] · quick-add · client/src/components/quickadd/useQuickAdd.js:107 · Reschedule writes `dueTime: item.dueTime || '23:59'`. "Move my project to Monday" turns a 17:00 deadline into 23:59, and the preview (CommandPalette.jsx:237) hides that the time changed. · Fix: `...(item.dueTime ? { dueTime: item.dueTime } : {})`.
- [P2 polish] · outline re-import · client/src/context/AppContext.jsx:265,459 · On the existing-course path, `addCategory` runs in a loop and every call computes `position` from the same stale `courses` closure. All new categories get the same `position`, so their order on reload (`order('position')`, useSupabaseLoader.js:103) is arbitrary. · Fix: pass an explicit `position` (existing length + index).
- [P2 polish] · outline re-import · client/src/context/AppContext.jsx:467 · On the existing-course path, `addTask` omits `dueTime: dl.dueTime`. The new-course path includes it (:498), so re-imported deadlines default to 23:59. · Fix: pass `dueTime: dl.dueTime || '23:59'`.
- [P2 polish, suspected] · load race · client/src/context/AppContext.jsx:54-69 · `loadAll(uid).then(...)` has no cancellation guard. If user A's load is still in flight when user B signs in (slow network, or the SW's 5s NetworkFirst timeout), A's rows land in B's state and are persisted under B's localStorage key. · Fix: `let cancelled=false; …; return () => { cancelled = true }`, and check `uid === user.id` before setting state.
- [P2 polish] · SW data cache · client/vite.config.js:58-66 · Supabase REST GETs use `NetworkFirst` with `networkTimeoutSeconds: 5`. On a slow connection, `loadAll` gets day-old cached rows, treats them as truth and overwrites the local cache. After "Clear all data" (Settings.jsx:60-84), a slow reload can bring deleted rows back. Signed-out users' rows also stay in Cache Storage. Sign-out (AuthContext.jsx:61-73) clears only localStorage. · Fix: `NetworkOnly` for `/rest/v1` (the app already has its own localStorage offline cache), or `caches.delete('ultragrade-supabase-cache')` on sign-out and data clear.
- [P2 polish] · SW fonts · client/vite.config.js:50 · Only `fonts.googleapis.com` (the CSS) is runtime-cached. The woff2 files come from `fonts.gstatic.com` and are never cached, so the offline PWA falls back to system fonts. · Fix: add a CacheFirst route for `^https://fonts\.gstatic\.com/` (cacheableResponse 0/200), or self-host the fonts (see size wins).
- [P2 polish] · theme-color · client/index.html:6,16 + useThemeTransition.js · Nothing updates `<meta name="theme-color">` when the theme is toggled at runtime (grep finds only index.html). The values `#0b1511` and `#eef2ef` also don't match the painted body (`[data-theme] body { background:#101612 / #f5f6f3 }`, index.css:396-397, which overrides the moss and pearl gradients at :38-49). The same mismatch applies to the manifest `theme_color`/`background_color` `#0b1511` vs the daisyUI `base-100` `#101612`. · Fix: set the meta in the theme effect, and align all colours to base-100.
- [P2 polish] · iOS PWA · client/index.html:37 · `apple-mobile-web-app-status-bar-style: black-translucent` always draws white status-bar glyphs. In the light theme (`#f5f6f3`) the clock and battery are near-invisible in standalone mode. · Fix: use `default`, or make the safe-area strip a dark band in the light theme.
- [P2 polish] · Dashboard · client/src/pages/Dashboard.jsx:42,47 · `now = new Date()` is created on every render and used as a `useMemo` dependency, so `todaySchedule` is recomputed on every render (the memo does nothing). The page never updates at midnight: a PWA left open shows yesterday's "today" schedule and tasks until something re-renders it. · Fix: `const [now, setNow] = useState(() => new Date())` with a timer to the next midnight, and use `dateKey(now)`/`now.getDay()` as the memo keys.
- [P2 polish] · Dashboard · client/src/pages/Dashboard.jsx:64 · The prompt chips ("What is due next?", "Import my outline", "Plan my week", "Find my professor") only dispatch `ug:assistant`. The chip text is dropped and the palette opens empty. · Fix: send the text in `CustomEvent.detail` and prefill `setText` in CommandPalette.
- [P2 polish] · dates · client/src/utils/commandCenter.js:3 (also LifeHub.jsx:21) · `Math.ceil((date T12:00 − now)/day)` changes value at noon. For a permit expiring 2026-11-18, it reads 2 days at 08:00 on 11-17 and 1 day at 13:00. On the expiry day after noon it reads `-0`, which triggers "The recorded date has passed". · Evidence: scratchpad/tz.mjs. · Fix: `daysBetween(today(), date)` from dateHelpers.
- [P2 polish] · dates · client/src/lib/googleCalendar.js:81-84 · `new Date('YYYY-MM-DD')` parses as UTC midnight. `timeMax` for endDate 2026-12-18 becomes Dec 18 19:00 Toronto, so events after 19:00 on the term's last day are not imported. · Fix: `new Date(`${endDate}T00:00:00`)` plus one local day.
- [P2 polish] · settings · client/src/utils/dateHelpers.js:121-129 · The `weekStartsOn` setting (Settings.jsx:234) is stored and synced but nothing reads it. `generateCalendarMonth` hardcodes Monday. · Fix: pass `settings.weekStartsOn` through to the offset, or remove the setting.
- [P2 polish] · routing · client/src/pages/Login.jsx:386,418,427 · RequireAuth stores `state.from` (App.jsx:45), but Login always navigates to `/`. Deep links and the manifest shortcuts (`/grades`, `/planner`) are lost when the session has expired. · Fix: `navigate(location.state?.from?.pathname || '/', { replace: true })`.
- [P2 polish] · routing · client/src/App.jsx:101 · `/onboarding` sits outside RequireAuth. A signed-out visitor can complete the wizard into the guest localStorage namespace, then `navigate('/')` sends them to /login and the data never syncs. A user who has already onboarded can also re-run it and create an extra semester. · Fix: wrap it in RequireAuth, and redirect away when `settings.studentType` is already set.
- [P2 polish] · demo assistant · client/src/components/demo/DemoAssistant.jsx:15-17 · `getReply` mutates state immediately while the card says "Preview ready". `/complete|finish|proposal/` is tested before `/reschedule|move/`, so "move my proposal to Monday" toggles completion instead of rescheduling. It also *toggles*, so asking twice un-completes the task while the reply says "completed". Running "Import my syllabus" again adds nothing (dedupe) but still claims "Added 2 deadlines". · Fix: test reschedule first, use `updateTask(id,{completed:true})`, and build the reply from the actual result.
- [P2 polish] · demo provider · client/src/demo/DemoProvider.jsx:29-31,57-65 · Coverage is complete: a scripted check found every `useApp()` key the UI reads in both providers. Nothing would throw "x is not a function", and `addCategory` returns the created category like the real one. Gaps: demo `addCourse` sets no `color`/`targetGrade`/`finalGradeOverride`. Demo `importFromOutline` for a *new* course drops assessments, deadlines and schedule (only `addCourse`). Demo `updateSchool` doesn't apply the default GPA scale. · Fix: mirror the real defaults and the import path.
- [P2 polish] · server errors · server/index.js:85-91 · The global handler always returns 500. body-parser errors (malformed JSON → `err.status 400`, >100kb → 413) are reported as "Internal server error" and logged with a full stack. · Fix: `res.status(err.status || err.statusCode || 500)` and expose the message for status < 500.
- [P2 polish] · ICS feed · server/routes/calendar.js:65; server/utils/ics.js:79-81 · A secret-token personal feed is served with `Cache-Control: public, max-age=3600`, so shared proxies may cache it. `DTEND` equals `DTSTART`, giving zero-length events, although the comment says "30-minute default block". · Fix: `private, max-age=3600`, and add 30 minutes to DTEND.
- [P2 polish] · immigration · server/routes/immigration.js:8,15 · `?force=true` lets unauthenticated callers bypass the cache and trigger an upstream canada.ca fetch, up to 60/min per IP. · Fix: ignore `force` unless the caller is authenticated as an admin (or drop it; the cron job revalidates).
- [P2 polish] · Modal · client/src/components/ui/Modal.jsx:61-66 · Initial focus goes to the first focusable element, which is the header Close (X) button in every titled modal. Forms (AddTask, AddCourse, AddSemester) open with focus on X instead of the first field. · Fix: prefer `[autofocus], input, select, textarea` before falling back to buttons.
- [P2 polish, suspected] · Modal/iOS · client/src/components/ui/Modal.jsx:108-118 · On mobile, the sheet's `drag="y"` makes framer set `user-select:none; -webkit-touch-callout:none` on the whole dialog (framer use-props.mjs:35-47), so modal text can't be selected or copied. `max-h-[85vh]` uses the large viewport, so with the iOS keyboard open the lower fields sit under the keyboard. The body scroll lock does nothing here because `<main>` is the scroll container, but nothing scrolls behind the overlay either. · Fix: attach drag only to the grab handle (`dragListener={false}` + `useDragControls`), and use `max-h-[85dvh]`.
- [P2 polish] · CommandPalette · client/src/components/quickadd/CommandPalette.jsx:25 · `if (demo) return <DemoAssistant/>` comes before the hooks (rules-of-hooks). It's safe today because demo and real Layouts are separate route instances, but it breaks if `demo` ever changes on a mounted instance. · Fix: split into `CommandPalette` and `RealCommandPalette`.

Answers to the specific questions:
- **`index.es-*.js` (151,365 B raw / 47.1K gz)** is **canvg** (jsPDF's optional SVG renderer) plus its core-js polyfills. It is **lazy**: only jspdf.es.min imports it, via `import()`, and only inside `addSvgAsImage`. The app never calls that, so browsers never fetch it. Its only cost is the SW precache.
- **framer-motion is eager**. It is pulled in by `main.jsx:4` (`MotionConfig`), Login.jsx:4 (eager route), BottomNav.jsx:2 and InstallPrompt.jsx:2 (via Layout), and Modal.jsx:3 (via the always-mounted CommandPalette→Modal and DemoAssistant). vendor-motion also contains the `react` package itself (a manualChunks/rolldown bucketing side effect), so the chunk can't be made lazy until that is fixed.
- **vendor-ui contains @dnd-kit (core+sortable+utilities+accessibility ≈ 43K raw / 14.4K gz) and @number-flow (17K raw / 5.7K gz)** and is in the **initial** set: it is modulepreloaded, and index.js imports sonner and cmdk from it. Both libraries are used only by lazy routes (CourseCard/CategoryRow in Grades; AnimatedNumber in Dashboard/Grades widgets). They load eagerly only because manualChunks groups them with sonner and cmdk.

### PWA / SW / manifest
- Precache: 64 entries (57 unique; the 7 icons are listed twice with identical revisions, so workbox dedupes them and it's harmless), **2232 KiB raw / ~770 KiB gzip downloaded at install**.
- Precached entries over 20 KB: jspdf 390K, html2canvas 195K, index.js 193K, vendor-supabase 191K, css 154K, vendor-react 153K, canvg 148K, vendor-ui 135K, vendor-motion 117K, Grades 46K, splash 1284/1290/1242/1179/1170/1125 (36–44K each), autotable 29K, purify 26K, splash-828 24K, pwa-512 23K.
- **Should not be precached:** html2canvas + canvg + purify (369K raw / 102K gz, never fetched by this app). jspdf + autotable (420K raw / 134K gz, used only on export; runtime-cache instead). The 9 iOS splash PNGs (300K raw / 171K gz). iOS reads `apple-touch-startup-image` itself at home-screen launch and never goes through the SW, so Android and desktop download 300K for nothing.
- manifest.webmanifest: valid JSON. Has name/short_name, `display: standalone`, `start_url: /`, `scope: /`, icons 64/192/512 plus a separate `maskable` 512, and shortcuts. Issues: `theme_color`/`background_color` `#0b1511` ≠ the painted base-100 `#101612`. No light-scheme variant. Shortcut icons lack `type`. `orientation: portrait-primary` locks iPad and desktop installs to portrait (a deliberate choice?). Shortcuts `/grades` and `/planner` lose their target after login (Login ignores `from`).
- client/index.html: the Google Fonts stylesheet is **render-blocking** and third-party (2 extra origins, preconnected). It requests 11 weights across 3 families. **Inter is only ever a fallback** (CSS has `font-family: Hanken Grotesk, Inter, …`), so its @font-face block is dead weight. The iOS meta set is present (capable, title, apple-touch-icon, 9 startup images). The status bar is `black-translucent`, which is wrong for the light theme. The pre-paint theme script reads the wrong localStorage key (P1 above).

## Top size wins (prioritised, initial-load gzip unless noted)

1. **Split @dnd-kit and @number-flow out of vendor-ui.** Change the manualChunks regex to `(sonner|cmdk)` only and let rolldown put dnd-kit and number-flow with Grades/Dashboard. **≈ −20 KB gz** (14.4 + 5.7). Trivial change.
2. **Replace axios with `fetch`** in useQuickAdd.js:47, OutlineImportModal.jsx and Immigration.jsx (or at least `await import('axios')` inside `submit`). **≈ −16.8 KB gz** (43.8K raw in index.js).
3. **Make Login (and WelcomeIntro) lazy**, so react-hook-form leaves the entry for signed-in launches (the common PWA case). Preload it when `!user`. Login 15.9K + WelcomeIntro 7.7K + RHF 23.6K raw ≈ **−15 KB gz** for signed-in users.
4. **Render the CommandPalette body lazily.** Keep the FAB and the ⌘K listener eager, and `lazy()` the `<Modal>` + cmdk (+ radix dialog/remove-scroll) on first open. cmdk stack ≈ 15 KB gz, plus CommandPalette code ~3 KB. **≈ −15–18 KB gz**. Combined with #3, Modal is then no longer eager either.
5. **Lazy-load the whole `/demo` branch.** DemoProvider, DemoWalkthrough → DemoOnboarding → **OnboardingWizard** (10.2K raw), DemoAssistant, fixtures ≈ 26K raw ≈ **−8 KB gz**, and OnboardingWizard then ships only with /onboarding.
6. **Use `@supabase/auth-js` + `@supabase/postgrest-js` directly** instead of `createClient`, since realtime, phoenix, storage and iceberg are unused. Measured 49.1 → 25.4 KB gz, **≈ −23.7 KB gz**. Medium refactor (lib/supabase.js is the only construction point).
7. **framer-motion:** switch to `LazyMotion features={domAnimation}` + `m.*`, measured 36.8 → 25.2 KB gz, **≈ −11.6 KB gz**. Better: replace BottomNav/InstallPrompt motion with CSS. Once #3 and #4 are done, `MotionConfig` is the only eager user, so moving it into the lazy pages takes **≈ −35 KB gz** off the initial set. Fix the react-in-vendor-motion bucketing first (add `react/` explicitly ahead of the framer rule, or return `vendor-react` for `scheduler|react-router|@remix-run`).
8. **Fonts:** drop Inter from the Google Fonts URL (fallback only), and request Hanken as a variable range `wght@400..800` (one file instead of 5). Then self-host the woff2 under `/fonts` (precached, `<link rel=preload>`, no render-blocking third-party CSS). Estimated −40–80 KB of font transfer on first visit, plus removing 2 third-party connections from the critical path (not measured; depends on Google's subsetting).
9. **SW precache diet (install payload, not initial):** add `globIgnores: ['**/html2canvas-*','**/index.es-*','**/purify.es-*','**/jspdf*','splash/**']` and a runtime CacheFirst for `/assets/jspdf*`. **−406 KB gz / −1089 KB raw** precache (102 + 134 + 171 gz). Also add a gstatic font route (P2 above).
10. **CSS (24.8 KB gz):** about half is DaisyUI component CSS. Use `daisyui.logs:false` and audit unused components, or set `styled:false` for unused parts. Uncertain, roughly −3–6 KB gz.

Achievable with 1–5 (low-risk): roughly **266.8 → ~190 KB gz** initial for signed-in users. With 6–7 as well: **~130–145 KB gz**.
