Viewports: iPhone SE 375x667, iPhone 15 393x852 (full journey), iPhone 15 Pro Max 430x932.

No horizontal page overflow was found on any route at any width (`scrollWidth === innerWidth` everywhere; the only overflowing elements are inside clipped scrollers: chip rows, day selector, GPA table).
Every input, select and textarea computes to ≥16px (a mobile rule forces 16px even on `text-xs`/`input-xs` fields), so iOS focus-zoom is not a risk.

Console: no `error` or `warn` messages in any journey. Only DevTools "issues": missing autocomplete, form fields without id/name (×5-6), fields without an associated label (×1-6). The /api server was not hit; demo Ask answers are local.

## What works well

- No horizontal overflow at 375/393/430. Long chip rows and the day selector scroll inside their own containers.
- Every form control is ≥16px, so there is no iOS zoom-on-focus.
- Modal system: bottom sheet on mobile, Escape closes, backdrop tap closes, the Close button is 44x44, focus moves into the dialog, Tab is trapped, and body scroll is locked.
- Core data flows work in the demo. Adding a category (weight total warning appears), adding a grade (Labs 92% → 81%, letter A+ → A-, GPA Summary 3.70) and adding a task (lands in "Today & tomorrow") all update live. Completing a task triggers a toast with a "Log grade" shortcut. Edit/reschedule moves the task to "This week". Adding a class works.
- The welcome intro theme picker switches the whole screen live, and the View-Transition circular reveal on the login theme toggle is smooth.
- Grades, Planner and Timetable icon buttons mostly carry descriptive aria-labels (`Edit task "Project proposal"`, `Delete CSC309`), and many use the `hit-44` overlay.
- Ask suggestion chips give instant, deterministic previews with a clear "Ask another" reset and a legal-advice disclaimer.
- The demo onboarding → walkthrough → Ask flow is coherent and well written.
